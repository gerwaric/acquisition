## Search Stage 5 Audit

Stage 5’s architectural direction is coherent, but I found several issues worth addressing before implementation. The most important is that the new pseudo-stat inventory overstates what its evidence establishes.

1. **The pseudo classifier cannot support its claimed mechanism counts.** It classifies by identifier patterns and assigns every unmatched entry to “weighted sum of lines.” Yet the captured renderer maps `pseudo_ritual_unique_monsters` and `pseudo_ritual_other_monsters` to properties, and the classifier calls them line sums. Its line-count category also includes `Has # Influences`. Additionally, the captured Carnal Boots have one crafted modifier producing two lines—so counting crafted lines does not establish a modifier count. Replace the aggregate certainty with per-entry evidence and an unresolved category. Your accepted sums/counts/derived-fields architecture can stand; the claimed partition of all 298 pseudos cannot. [Classifier](/Users/tom/Development/GitHub/gerwaric/acquisition/spikes/rust-playground/search/trade-query/scripts/classify-pseudo.py:26), [property mappings](/Users/tom/Development/GitHub/gerwaric/acquisition/spikes/rust-playground/search/trade-query/data/grammar.json:1790), [crafted example](/Users/tom/Development/GitHub/gerwaric/acquisition/spikes/rust-playground/search/trade-query/data/fetch-census.json:1920).

2. **The SQL withdrawal was not propagated through the active framing.** Note 22’s stance 6 still requires SQL as a surface and an MCP SQL tool, while its floor section withdraws that requirement. This is especially consequential because C101 and C102 still cite its stances. Rewrite the current stance; preserve the earlier requirement through history. [Contradictory stance](/Users/tom/Development/GitHub/gerwaric/acquisition/spikes/rust-playground/brainstorming-notes/22-search-framing.md:62).

3. **Counts have no stated rule for unavailable grouping keys.** C95 specifies missing and unreadable *summed values*, but not grouping fields. Consider counting all items by class when one readable item has no class mapping: the query matches it, but does it enter an “unclassed” bucket, an undecided bucket, or get omitted with a diagnostic? Crossed counts compound this problem. Settle this before the builder chooses silently, and pin an example where bucket counts reconcile with the answer’s total. [C95](/Users/tom/Development/GitHub/gerwaric/acquisition/spikes/rust-playground/decisions/search.md:20).

4. **Realm-specific vocabulary fragments need a representation.** C97 promises an exact selecting term for each `(realm, kind, template)` row under an all-realms search. C96 moves realm outside the conditions, and §2b rejects realm syntax except an unambiguous scope abbreviation. For identical templates in two realms, how does a pasted fragment select just one row while remaining composable? A realm-qualified line selector could solve this, but that rule is not stated. This is a contract gap, not evidence that the scope decision is wrong. [C96–C97](/Users/tom/Development/GitHub/gerwaric/acquisition/spikes/rust-playground/decisions/search.md:21), [scope mechanism](/Users/tom/Development/GitHub/gerwaric/acquisition/spikes/rust-playground/brainstorming-notes/28-search-ruling-packet.md:207).

5. **The combined page is not yet usable for the promised mistake walk.** It describes two count spellings without supplying either, mentions bounded `holds(…)` without its syntax, and provides no concrete socket-group, source/flag, or sort examples. The latest range-total and derived-field additions are also largely outside it. A reader must invent notation or consult the old proposals, which would weaken the exercise. Before that walk, make this page a small, self-contained language reference with executable-looking examples; implementation can still wait. [Combined page](/Users/tom/Development/GitHub/gerwaric/acquisition/spikes/rust-playground/brainstorming-notes/28-search-ruling-packet.md:53).

6. **“Mechanism” now contains observable contract rules.** The selected sorting maximum, truth propagation, diagnostic denominators, and incomplete-sum comparisons all live in §2b. These determine answers; they are more than replaceable implementation details. The registry’s explicit pointer helps, but the packet also calls itself history, and CONTEXT treats exceeding the byte limit as proof that text is mechanism. Label the retained section as the binding contract detail until transferred, and treat byte counts as routing prompts rather than semantic tests. This needs clearer authority, not longer duplicated bullets. [Retained section](/Users/tom/Development/GitHub/gerwaric/acquisition/spikes/rust-playground/brainstorming-notes/28-search-ruling-packet.md:127), [budget rule](/Users/tom/Development/GitHub/gerwaric/acquisition/spikes/rust-playground/CONTEXT.md:21).

7. **The reference-data boundary remains ambiguous.** C102 says base defences are game knowledge belonging to the user, while §2b prescribes a base-defence-percentile function using reference data. Both could coexist if the distinction is between measured base data and the user’s judgments, but the current wording does not draw that distinction. Clarify which reference-backed derivations are authorized. [C102](/Users/tom/Development/GitHub/gerwaric/acquisition/spikes/rust-playground/decisions/search.md:30), [percentile function](/Users/tom/Development/GitHub/gerwaric/acquisition/spikes/rust-playground/brainstorming-notes/28-search-ruling-packet.md:246).
