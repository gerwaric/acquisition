# `acq-mcp` — tool reference

Generated by `crates/acquisition-mcp/tests/mcp_reference.rs` from the server's own `initialize` instructions and `tools/list`; a golden file the test keeps equal to the binary. Do not edit: change the tool's attributes in `crates/acquisition-mcp/src/main.rs` and regenerate with `ACQ_UPDATE_FIXTURES=1 cargo test -p acquisition-mcp --test mcp_reference`. The CLI's verbs are `CLI-REFERENCE.md`.

## Instructions (sent at `initialize`)

Acquisition playground (provider: mock). Items: search answers a query over every item the store holds — counts for each term, the total, then rows or tables — describe prints its query language, and show is one item whole. Their arguments and answers are JSON; every count in an answer holds the request that returns its members, sent back as printed, and a refusal is a result marked isError with readings and offers to go on from. Begin with describe, or search with no arguments. The store tools (search, describe, show, accounts, tabs, characters, search_items, get_item, store_status, item_events) read the shared SQLite store directly — no daemon, no network. The refresh slice: sync_policy / set_sync_policy declare intent (local, sends nothing; replacing a policy must name the revision it replaces), refresh_plan compiles it offline into the explicit bounded action set for review, and apply_plan spends exactly that plan as one parent job. Job tools talk to the local daemon; API requests are jobs (submit_job returns an id; poll job_status, then job_result). Rate-limit holds can reach ~5 minutes — a waiting job is the limiter working. Login is done by the human via the `acq` CLI; this server never spawns or replaces a daemon in real-GGG mode — there it submits, applies and quotes only through one a human already started (C14).

## Tools

### `accounts`

Accounts this machine has logged into (from the store's non-secret index; no daemon).

No arguments.

### `apply_plan`

Execute a reviewed plan: exactly its actions, as one `apply` parent job the daemon admits or refuses whole at submit (single-request vocabulary + the max_requests budget). Refused offline — before any daemon contact — if the stored sync-policy revision moved since the plan (replan with refresh_plan). In real-GGG mode the daemon must already be running (a human starts it; this server never spawns one there). An empty plan is a no-op with no daemon contact. Returns the parent job id; poll job_status, then job_result.

- `account` (string | null)
- `max_requests` (integer | null) — Refuse at admission — before any child job exists — if the plan authorizes more logical requests than this.
- `plan` (object, required) — The plan envelope exactly as refresh_plan returned it (the `plan` field). Re-validated here; a tampered or hand-built envelope will not parse.

### `cancel_job`

Cancel a waiting or running job; cascades to its descendants.

- `id` (integer, required) — The job id, as returned by submit_job.

### `characters`

Characters known to the store, with class, level, league, item counts, and whether the full character (equipment + inventory) has been fetched (no daemon, no network). Fresh data is a `characters` or `character` job.

- `account` (string | null)
- `league` (string | null) — Restrict to one league; omitted lists every league.
- `realm` (string | null) — Restrict to one realm (pc, xbox, sony, poe2); omitted lists every realm.

### `daemon_status`

The daemon running: its identity (C84, C83) — contract revision, the executable it runs from and its hash (artifact), the world it serves (its canonical store root), the socket it was reached on (derived from the world), how that file relates to the acqd beside this server (artifact_relation: same_file, same_bytes for another copy, different, unhashable, no_sibling, unreported), which of the four dimensions match (contract_matches, artifact_matches, provider_matches, world_matches), and under wanted this server's own version, contract, provider and world with that sibling — all from the one look that judged the daemon; and, when compatible, its vitals: provider, uptime, connections, queue counts, rate-limit policies learned, rails state (with the journal path), keyring health, and log — the log file the daemon opened, as it reports it. Observes only: running=false when no daemon is up, with persisted — what the ledger on disk holds (C45): waiting, recorded_running, written_at; null when this shell's world has no queue yet; running=true, compatible=false for a daemon of another contract, artifact, provider or world, reported by its identity alone and never replaced by this server; running=true, responsive=false (with socket and lock_holder, the pid the world's lock records) for something that accepted the connection and did not answer hello within 5s — a wedged daemon, for a human to stop by hand.

No arguments.

### `describe`

The query language `search` takes, as this build knows it (no store read): fields, what a line has, operators, closed value sets, slots, the computed values with their definitions, what a count takes, what is not built and the limits stated — or only the entries named. Read it before a first query; a name it does not know is refused with the near names.

- `names` (array | null) — Only these entries: a field, a computed value, or a section — `league`, `line`, `total_res`, `counts`. Omitted: the whole language.

### `get_item`

One item by id, verbatim as GGG returned it (no daemon, no network).

- `account` (string | null)
- `id` (string, required) — The GGG item id (from search results).

### `item_events`

Item events (added/moved/changed/removed) from recent ingests (no daemon, no network).

- `account` (string | null)
- `hours` (number | null) — How far back to look (default 24 hours).
- `limit` (integer | null) — Maximum rows (default 200).

### `job_result`

A finished job's payload or error; answered across daemon restarts (the queue persists). Payloads can be large — prefer the store tools for reading data.

- `id` (integer, required) — The job id, as returned by submit_job.

### `job_status`

One job's state, ETA, and retries. A waiting job with a large ETA is the rate limiter holding, not a hang (holds can reach ~5 minutes).

- `id` (integer, required) — The job id, as returned by submit_job.

### `list_jobs`

Jobs the daemon knows about this lifetime, with states and ETAs. Observes only (C10): with no daemon running it never spawns one and answers from the ledger on disk instead (C45) — running: false, persisted: the non-terminal rows as the last daemon left them (jobs, without ETAs) and written_at, how old that picture is; persisted is null when this shell's world has no queue yet. A job command from the CLI spawns a successor that restores them.

No arguments.

### `refresh_plan`

Compile the stored sync policy + facts on record into a RefreshPlan for one (realm, league): the explicit, bounded action set applying would execute — stash listing and tab fetches, the realm's character listing and character fetches, each facet as the policy covers it — with per-action reasons, skipped tabs and characters, unknown ids, and a coarse wire estimate. Offline — sends nothing, spends nothing. A running daemon adds its read-only quote (ETA + rate-limit headroom; never spawned for this); `quote_note` says why one is absent. Review the plan, then hand `plan` to apply_plan.

- `account` (string | null)
- `league` (string | null) — League name; defaults to "Standard".
- `realm` (string | null) — Realm: pc (default), xbox, sony, or poe2 (a poe2 plan can carry character work only).

### `search`

Item search over the shared store (no daemon, no network): a query in the language `describe` prints, asked of every item in scope. The arguments are the request: {} is every item; {"query": {"text": "class:ring rarity=rare"}} is a query. The answer is one JSON document: `query` (the text as understood, and its tree), `scope` (account, realm, what was and was not fetched), `basis` (what the answer was computed from), `terms` (for each term how many items matched, failed, lacked the thing or were undecided), `total`, `view`, and `rows` — id, name, base, rarity, place by name and id, and the lines each term touched, never the item's body, which is `show`. Rows past the limit are counted in `view.rows.left_out`, and `view.rows.next` is the request for the rows after: send it back whole. Every count that is not zero holds the request that returns exactly its members, and a zero total offers requests under `zero.offers`: any of them is sent back as printed. A count-first look is {"view": {"counts": {"keys": ["tab", "rarity"]}}}; the vocabulary of lines is the key `line`, or `line:<text>` narrowed. `describe` and the messages name a terminal's flags: --count, --cross, --sum, --sort, --desc, --limit and --explain are `view`'s fields, --context is `context`, --realm and --membership are `scope`'s, and --next is `view.rows.next` sent back. A refusal is a result marked isError: `error`, `kind`, `readings` (what may have been meant: query texts, or what to name) and `offers` (requests to send instead).

- `basis` (object) — Carried by a continuation, as an answer's `next` holds it; never written by hand.
- `context` (string) — "matches" (the default), or "corpus": the view over every item in scope, the query set aside.
- `count` (integer) — Beside `request`, the count it was printed with: the answer then says under `before` where the count has moved.
- `counted_at` (object) — Beside `request` and `count`, the `basis` of the answer the count came from: the answer then says under `before` wherever the basis has moved.
- `query` (object) — {"text": a query in the language `describe` prints} or {"tree": the tree an answer returned}, never both. Omitted: every item in scope. A refinement is the old text in parentheses and a new term.
- `request` (object) — In place of the fields above: a request as an answer holds one — a count (`count`, `denominator`, `request`), `view.rows.next`, or an offer — sent whole, as printed.
- `scope` (object) — What is searched: {"account": a username or uuid, needed only when several accounts are known; "realm": pc, xbox, sony, poe2 or all, needed only when the store holds several; "membership": "live" (the default) or "all", which adds removed items, each row marked with when it left}.
- `view` (object) — One of: {"rows": {"limit": N, "sort": a value, "desc": true}}, the default, 20 rows where no limit is given; {"counts": {"keys": [a key, …], "sum": a value, "limit": N}}, a table for each key and no rows; {"cross": {"keys": [two keys]}}, one crossed table; {"explain": {"path": a node's path, a term's as `terms[].path` gives it}}, the total with that node forced true and forced false. `describe` with names ["counts"] lists the keys.

### `search_items`

Substring search over item name/type/base in the shared store; socketed gems are rows too (no daemon, no network).

- `account` (string | null)
- `include_removed` (boolean | null) — Include items no longer seen at their last location.
- `league` (string | null) — Restrict to one league.
- `limit` (integer | null) — Maximum rows (default 50).
- `realm` (string | null) — Restrict to one realm (pc, xbox, sony, poe2).
- `text` (string, required) — Substring matched against item name, type line, and base type.

### `set_sync_policy`

Write the per-account sync policy (validated strictly, compare-and-swap on if_revision). Sends nothing — intent is local; the network cost appears only when a plan is applied. Replacing an existing policy requires if_revision (from sync_policy); a stale or missing revision is a conflict, never a clobber.

- `account` (string | null)
- `if_revision` (integer | null) — The revision this write replaces, from sync_policy. Required when a policy exists (replacing intent you have not read is refused as a conflict naming the current revision); omit only to create the first policy.
- `value` (object, required) — The sync-policy value, e.g. {"version":3,"realms":{"pc":{"leagues":{"Standard":{"tabs":"all","characters":"all","max_age_seconds":3600}}}}} — per league, `tabs` and/or `characters` ("all" or an id list; absent means no coverage of that facet; an entry covering neither is refused). `tabs` is refused under realm poe2 (stashes are PoE1 only); `characters` is taken under every realm. Older values still parse: a version-1 top-level `leagues` map as realm pc, and version 1/2 as tab coverage only. Validated strictly before anything lands — a typo'd field is refused, never half-honored.

### `show`

One item as the search derives it, live or removed (no daemon, no network): its place, its fields, class, category and price, and every line with its kind, template and numbers. `against` adds why the item does or does not match a query: the root's outcome and each term's. `body` adds the stored body, verbatim. An id that is a tab's or a character's is refused and offers the search that lists it. A refusal is a result marked isError, as `search`'s is.

- `account` (string | null) — Account selector (username with or without `#discriminator`, or uuid); required only when several accounts are known.
- `against` (object) — Why the item does or does not match a query: `{"text": …}` or `{"tree": …}`, as a request's `query`.
- `body` (boolean | null) — Also return the body as the store holds it, verbatim.
- `id` (string, required) — An item's id, whole, as an answer printed it.

### `store_status`

Store file path, size, and row counts (no daemon, no network).

- `account` (string | null)

### `submit_job`

Submit a job to the daemon and return its id immediately; poll job_status then fetch job_result. In real-GGG mode the daemon must already be running (a human starts it; this server never spawns one there).

- `account` (string | null) — Account to run as; required when several sessions are live.
- `kind` (string, required) — Job kind: profile, characters, character, leagues, stashes, stash, refresh (mock daemon also: sleep, fetch, whoami).
- `params` (object) — Kind-specific params, e.g. {"league": "Standard", "id": "..."} for stash. Passed verbatim; visible to every connected client.
- `priority` (integer | null) — Higher runs sooner (default 0).

### `sync_policy`

The per-account sync policy (declared coverage + freshness, an annotation) with its revision — the intent refresh_plan compiles. Reads the store; no daemon, no network. `policy` is null when none is set.

- `account` (string | null)

### `tabs`

Every stash tab of a league, a flat list in which a substash names its `parent`, with item counts and fetch times, from the shared store (no daemon, no network).

- `account` (string | null) — Account selector (username with or without `#discriminator`, or uuid); required only when several accounts are known.
- `league` (string | null) — League name; defaults to "Standard".
- `realm` (string | null) — Realm: pc (default), xbox, or sony.
