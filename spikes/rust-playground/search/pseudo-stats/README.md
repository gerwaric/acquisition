# pseudo-stats — which mechanism answers each of the site's 298 `pseudo` stats

Status: first pass complete — 2026-09-18. Per-entry classification against the
committed captures; every non-`unresolved` row names an input path and a
locator a reader can open. Per-entry detail is `data/pseudo-classes.csv`
(298 rows), regenerated byte-for-byte by `scripts/classify.py`, which prints
the counts below.

Headline:
- 189 of 298 entries land in a substantive class on a named input; **109 are
  `unresolved`**, each with the one read that closes it. The previous script
  (`../trade-query/scripts/classify-pseudo.py`) left none.
- The site answered two entries itself, in the fetch capture. The strongest
  evidence in the track is q4's Crusader Plate: `+94.5 total maximum Life`
  over `+90 to maximum Life` and `+9 to Strength` — the *weight* (0.5 per
  Strength), not just the sum, from the site's own `pseudoMods` line.
- 13 `pseudo` keys are **properties** in the renderer's own table, the two
  ritual entries among them (`property_type_to_field.table.106`, `.107`);
  86 temple rooms and 17 quality entries are properties the private item
  carries. `field` is the largest class at 123.
- `computed` is **empty**: `#% Base Defence Percentile` is its only candidate
  and `repoe/README.md` names no per-base defence ranges among its five
  extracts, so no input supports it. `ranged-total` holds the 15 `Adds # to #`
  texts whose own template the census shows; the 6 aggregate ones do not.
- Three families are unresolved wholesale because the owner's corpus has no
  such item: 53 lake reflections, 19 logbook entries, 1 tablet-islands entry.
  `mod-templates.csv` has **no** `Has Room:`, `Has Logbook` or `Reflection of`
  line — the brief expected it to; temple rooms turned up in
  `properties-census.csv` instead, as type-49 property values.
