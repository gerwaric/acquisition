# M3 ledger

Every run of M3 — a CLI ask, process start to exit, over a `.backup`
copy of the owner's facts — one row a build, in order. The command, the
copy and what the first runs showed are `MEASUREMENTS.md` ("M3, M4" and
"M3 at each later build"); the script is
`item-facts/scripts/m3-ask.py`, run alone, after the three builds its
header names. Rows stay as written: a later run is a new row, never an
edit to an old one. No budget.

A row is the build's hash and where it stands, the first ask after the
copy is written, and the range of the warm medians of ten asks, release
and debug, in ms, with every release ask over 500 named. The load is the
empty query's release ask, and it alone is the persisted projection's
trigger; an ask over 500 by an evaluator's cost is the totals batch's
(`decisions/search.md`, "Parked").
