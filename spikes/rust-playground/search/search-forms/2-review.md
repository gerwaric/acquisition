8. **[agree, stronger than you put it] G1: the inline weighted sum is an unnamed total, and the evaluator already exists.** A C94 total row is `(line selector, slot | none, weight)`. ## The request, the tree, discovery

9. **[agree, with a text form] The request is what travels; and the `realm:pc` shorthand was reaching for a whole-request string.** People want one pasteable line; the shorthand faked it with a term-lookalike and, as you saw, broke `(old) new`. Honest version: a scope part that is syntactically not a term — `in pc: class:ring line(…)`, `in all: …`. `in …:` exists only at the front, cannot be parenthesised, negated or or-ed, so "never hoisted from a branch" is true by grammar instead of by an error. Refinement is `in pc: (old) new`. Every canonical text prints it, so a copied query cannot acquire another client's default; the parked sticky default becomes "an adapter fills the scope and the answer shows it filled". League, tab, character stay terms (C96). **[counter, mild]** I would keep *view* out of the text line. Scope changes which set is true; view is how one set is read (C100's three views of the same set). The JSON request carries scope + conditions + view whole — that is the GUI↔agent value; the text line carries scope + conditions; adapters spell view. Your strongest rebuttal is probably that `count by class` *is* the question, not a presentation. I am not certain here.

Both additive.
